Parte 1

1. window es la ventana del navegador

El modelo de objetos del navegador (BOM) es la forma en que JavaScript habla con el navegador. No hay un estándar oficial único para el BOM. El objeto que sí está en todos los navegadores es window: representa la ventana.

document es una propiedad de esa ventana. alert, setTimeout y el resto de las funciones globales también viven ahí. Una variable declarada con var y una función declarada con function quedan como miembros de window. Una declarada con let o const existe en el archivo y no aparece como propiedad de window. 

var nombreVentana = "El Break";

function saludoVentana() {
  return "Hola desde " + nombreVentana;
}

3. location es la dirección de esta página

window.location guarda la URL actual. Asignar una URL completa a location.href abre esa página. Estas cuatro propiedades son las que vamos a leer:

  • href: la URL completa.
  • hostname: el dominio del servidor.
  • pathname: la ruta y el nombre del archivo.
  • protocol: http:, https: o file:.

Parte 4

4. history se mueve como Atrás y Adelante

window.history es el historial de la ventana. Por privacidad, JavaScript no recibe la lista de direcciones visitadas. Sí puede moverse en esa lista, igual que los botones del navegador. 

history.back()
history.forward()

El primer botón anota una entrada en esta misma página con history.pushState. Recién ahí back() tiene a dónde volver sin salir de la clase. Si la entrada actual es el inicio, back() se iría de la página.

Parte 5

5. navigator describe el navegador

window.navigator guarda datos del navegador. Estas tres propiedades son las del material:

navigator.appName
navigator.appCodeName
navigator.platform

El botón lee las tres propiedades en este navegador.

appName y appCodeName quedaron fijos por compatibilidad. En los navegadores actuales suelen decir Netscape y Mozilla. No identifican Chrome, Edge ni Firefox. platform sí describe el sistema.

Parte 6

6. Tres cuadros emergentes

alert, confirm y prompt son métodos de window. Los tres pausan la página hasta que alguien responde.

alert

Informa. Hay un solo botón, Aceptar. No devuelve un dato: el resultado es undefined.

confirm

Pide una verificación. Aceptar devuelve true. Cancelar devuelve false.

prompt

Pide un texto. Aceptar devuelve ese texto. Cancelar devuelve null.

window.alert("El café de Ana está listo.");
const acepta = window.confirm("¿Confirmás el pedido de Ana?");
const nombre = window.prompt("¿Cómo te llamás?", "Ana");

Cada botón abre el cuadro y escribe acá lo que devolvió.

Parte 7

7. setTimeout espera. setInterval repite.

Un temporizador ejecuta una función después de una cantidad de milisegundos. setTimeout la corre una vez. setInterval la vuelve a correr, una y otra vez. Los dos son métodos de window. clearTimeout y clearInterval los frenan. 

const aviso = setTimeout(function () {
  // una vez, a los 2000 ms
}, 2000);

const reloj = setInterval(function () {
  // cada 1000 ms
}, 1000);

clearTimeout(aviso);
clearInterval(reloj);

El aviso del café usa setTimeout. El contador usa setInterval.

Parte 8

8. Una cookie recuerda un dato chico

Cuando el servidor terminó de enviar la página, la conexión se cierra y el servidor ya no tiene presente a la persona. Una cookie es un archivo de texto chico en la computadora, inventado para guardar ese recuerdo. Si Ana deja su nombre, la próxima visita puede leerlo.

En el navegador se escribe y se lee con document.cookie. El texto lleva el nombre, el valor, la fecha de vencimiento y la ruta. 

document.cookie = "cliente=" + encodeURIComponent("Ana")
  + ";expires=" + vence + ";path=/";

Del navegador al texto que viaja

Hasta acá JavaScript mira la ventana. Desde acá el pedido de Ana se convierte en texto JSON, el formato con el que ese dato puede ir a otra computadora y volver.

Parte 9

9. JSON es texto con forma de objeto

JSON significa JavaScript Object Notation. Es un formato de intercambio: texto plano, escrito con la notación de los objetos de JavaScript. Sirve para mandar datos entre computadoras y no depende de un lenguaje. Muchos lenguajes saben leerlo y generarlo.

Como se parece a un objeto de JavaScript, el programa lo convierte con dos funciones. JSON.parse toma el texto y devuelve el valor. JSON.stringify toma el valor y devuelve el texto.

Llega texto

El texto puro que viene de un servidor se usa como objeto de JavaScript.

Sale texto

Un objeto de JavaScript se envía como texto puro.

Se trabaja el objeto

En la página, el dato se maneja como objeto. La conversión la hacen parse y stringify.

const pedido = {
  cliente: "Ana",
  producto: "café",
  precio: 1800,
  cantidad: 2
};

const texto = JSON.stringify(pedido);
const otraVez = JSON.parse(texto);

Parte 10

10. La sintaxis cabe en cuatro reglas

  • Los datos son pares nombre/valor.
  • Esos pares se separan con comas.
  • Las llaves sostienen un objeto.
  • Los corchetes sostienen un arreglo.

El nombre va entre comillas dobles, después dos puntos, después el valor. "cliente": "Ana" es un par. En un objeto de JavaScript las comillas del nombre se pueden omitir. En JSON, no. 

{
  "cliente": "Ana",
  "producto": "café",
  "precio": 1800,
  "cantidad": 2,
  "paraLlevar": true,
  "nota": null,
  "extras": ["medialuna"]
}

Parte 11

11. Seis tipos entran. Tres no viajan.

Qué puede haber en un texto JSON
Entra No entra
string, number, object, array, boolean, null una función, un Date, undefined

JSON.stringify arma el texto con lo que sí entra. Una función y un undefined desaparecen del texto. Un Date sale como string, y al volver a leerlo ya no es una fecha.

Los botones muestran qué tipo tiene cada valor.

Parte 12

12. parse entra. stringify sale.

El pedido vive en un objeto. JSON.stringify lo deja en una cadena. JSON.parse lee esa cadena y rearma el objeto. Con el objeto se puede calcular precio * cantidad. Si el texto no cumple la sintaxis, JSON.parse lanza SyntaxError.

El total del pedido parseado aparece acá.
