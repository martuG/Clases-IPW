Maquetación web: el plano antes del código

Antes de programar un sitio hay que decidir cómo se organizan los espacios y los elementos. Esa decisión es la maqueta.

Objetivos

Parte 1

1. Maquetar es organizar el espacio

La maquetación web es la etapa en la que se estructuran, organizan y distribuyen de manera gráfica los espacios y elementos del sitio. Ahí se decide dónde van menús, imágenes, botones, videos, enlaces y títulos. Después viene una previsualización de cómo se verá el sitio terminado.

En esa misma etapa se eligen paletas de color, tipografías y estilo, para que el diseño cumpla los requerimientos y sea funcional. Sin esa decisión, el HTML y el CSS se escriben a ciegas.

Qué se ubica

Logo, navegación, contenido principal, imágenes, formularios, pie de página.

Qué se define

Jerarquía visual, colores, tipografías, márgenes y prioridades de contenido.

Parte 2

2. Sin plano, la casa se construye mal

Empezar un sitio sin un mapa de cómo debe ser puede ser igual de problemático que construir una casa sin planos. La maquetación previa organiza los elementos y permite ver cómo quedará el sitio una vez publicado.

Así se conoce cada pieza que el sitio realmente necesita y se diseña pensando en la organización y, sobre todo, en la persona que lo va a usar. Es la etapa en la que se puede definir un estilo propio.

Parte 3

3. La maqueta sirve a la UX

La experiencia del usuario (UX, user experience) es un factor decisivo para que alguien se quede en el sitio. La maqueta permite diseñar y rediseñar cuantas veces haga falta antes de invertir horas de programación.

También mejora el flujo entre diseño y software: menos idas y vueltas, menos tiempo perdido en codificar una disposición que después se descarta.

UX

Cómo se siente el recorrido: ¿se encuentra lo buscado? ¿los pasos son claros?

UI

Cómo se ve: botones, tipografía, colores e iconos.

Maqueta

Une las dos: fija la disposición (UX) y anticipa el estilo (UI).

Accesibilidad también se decide acá: contraste, tamaño de zona clicable y orden del HTML alineado con el orden visual. No es un parche al final.

Parte 5

5. El esqueleto se escribe en HTML semántico

En código, la maqueta empieza nombrando regiones. HTML5 aporta etiquetas que describen el rol de cada zona. Eso ayuda a lectores de pantalla, a buscadores y al equipo que mantiene el sitio. 

<body>
  <header>…</header>
  <nav>…</nav>
  <main>
    <section>…</section>
    <aside>…</aside>
  </main>
  <footer>…</footer>
</body>
Regiones semánticas
Etiqueta Rol
header Cabecera del sitio o de una sección.
nav Navegación principal.
main Contenido principal. Una sola vez por página.
aside Contenido relacionado (barra lateral u otro bloque secundario).
footer Pie de página. 
El botón escribe el esqueleto semántico.

Parte 6

6. Flexbox alinea. Grid arma el plano.

Con el modelo de caja ya visto, faltaba decidir cómo se organizan varias cajas juntas. Hoy casi todo el layout moderno se resuelve con dos herramientas:

  • Flexbox: una dimensión (fila o columna). Menús, botones en línea, alinear ítems.
  • CSS Grid: dos dimensiones (filas y columnas). Plano general de la página.

Suelen combinarse: Grid define las zonas; Flexbox ordena lo que hay adentro de cada zona.

B
C

Flexbox: los tres ítems comparten una fila y se espacian.

/* Flex */
.barra {
  display: flex;
  justify-content: space-between;
  align-items: center;
  gap: 1rem;
}
/* Grid */
.pagina {
  display: grid;
  grid-template-columns: 2fr 1fr;
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
}

Parte 7

7. Responsive y adaptativo no son lo mismo

Una forma moderna de diseñar es hacer sitios que se acomoden a distintos anchos. Hay dos caminos cercanos, pero no idénticos:

Responsive

Una misma maqueta fluye: unidades relativas, imágenes fluidas y media queries. Hoy suele arrancarse mobile-first.

Adaptativo

Se preparan layouts para anchos concretos (móvil, tablet, escritorio) y el sitio elige cuál mostrar.

Ambos buscan legibilidad y uso cómodo en celular y en escritorio. La diferencia está en cuánto se “reflujo” frente a cuánto se “cambia de plantilla”.

Parte 8

8. Bootstrap: grilla y componentes listos

Estos enfoques también se logran con frameworks de maquetación y plantillas prediseñadas. Bootstrap es un conjunto de herramientas de front-end: desde el prototipo hasta producción en tiempos más cortos.

  • Sistema de grilla de 12 columnas.
  • Componentes: navbar, cards, formularios, modales.
  • Utilidades de espaciado, tipografía y color.
  • Comportamiento responsive integrado.

Se puede incluir por CDN. La documentación oficial está en getbootstrap.com. 

<link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">

<div class="container">
  <div class="row">
    <div class="col-12 col-md-8">Contenido principal</div>
    <div class="col-12 col-md-4">Barra lateral</div>
  </div>
</div>

col-12 ocupa todo el ancho en móvil. Desde md, el contenido toma 8 columnas y el lateral 4.

Parte 9

9. Un flujo de trabajo corto

  1. Listar contenidos y prioridades.
  2. Armar wireframes de las pantallas clave.
  3. Definir paleta, tipografía y componentes (mockup).
  4. Validar con un prototipo liviano.
  5. Pasar a HTML semántico + CSS (Flex/Grid) o a Bootstrap.
  6. Probar en distintos anchos y con teclado.

La maquetación no reemplaza al código: lo ordena. Programar sin plano se puede, pero cuesta más tiempo y suele salir una experiencia peor.
